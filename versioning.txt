HDF5 SCHEMA VERSIONING AND MIGRATION STRATEGY

1. DESIGN PRINCIPLE
To ensure the pipeline remains flexible and backward-compatible without
cluttering downstream scripts with messy conditional (`if/else`)
statements, all file version checking and structural translation will be
completely centralized. Downstream code will never inspect or open HDF5
files directly; it will rely on a centralized loading utility.

2. SCHEMA VERSIONING MECHANISM
Every HDF5 file generated by the ingestion module will include a
mandatory string attribute stored at the root level:
- Attribute: `schema_version` (e.g., "1.0")

3. CENTRALLY MANAGED COMPATIBILITY
- The Entry Point: A dedicated loader function in the package acts as
  the sole translator.
- Handling Updates: When a file is loaded, the loader checks the
  `schema_version`. If an older version (e.g., Version 1.0) is
  encountered alongside a future version (e.g., Version 2.0), the
  loader dynamically reorganizes the data in memory before passing it
  downstream.
- Code Isolation: Downstream modules (preprocessing, graph generation,
  training) receive a uniform data object regardless of the file's
  underlying disk version. This isolates maintenance to a single
  function.

4. TARGET VERSION 1.0 BASELINE SCHEMA
- `/signals`: Numerical arrays containing voltage values (stored as 2D
  arrays for continuous files, or structured as separate independent
  arrays like `/signals/segment_0`, `/signals/segment_1` for
  discontinuous/EDF+D data).
- `/channels`: Channel names, unit types, and individual sampling
  rates.
- `/events`: Event markers, text annotations, start timestamps, and
  durations.
- `/metadata`: Global recording information (absolute start date and
  time, subject ID, equipment data).

5. INTEGRATION CONSTRAINTS FOR KREMBIL-KIT
- The implementation will be added cleanly into the existing package
  framework.
- Pre-existing classes and modules within `krembil-kit` will remain
  untouched and functional; new capabilities will be introduced as an
  isolated ingestion layer.
